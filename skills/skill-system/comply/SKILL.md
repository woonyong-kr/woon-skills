# Comply

목표는 지시 문구의 표면적 복종이 아니라 같은 요구에서 더 안전하고 정확한 결과를 재현하는 것이다.

1. 보장할 결과, 불변 조건과 금지 효과를 관찰 가능하게 정한다.
2. 수정한 trigger·권한·실패 경계에 관련된 기존 사례를 고른다. 효과 개선을 주장할 때는 승인본 또는 스킬 없는 실행을 같은 조건의 기준본으로 대조한다.
3. 결정적 검사를 우선하고 필요한 행동 사례를 한 번 확인한다. 실제 산출물·부수 효과를 먼저 판정하며 주관적 품질만 출처를 가려 비교한다.
4. 결과가 흔들리거나 미해결 실패·고위험 경계가 남을 때만 반복·미공개 질문으로 넓힌다. 횟수는 확인할 불확실성에 맞추고 고정 반복이나 무실패 라운드를 종료 조건으로 삼지 않는다.
5. 치명적 위반은 평균으로 상쇄하지 않는다. 원인을 고친 뒤 영향받는 사례만 다시 확인하고 같은 입력·환경의 통과 근거는 재사용한다.
6. 요청의 완료 기준을 충족하면 확인 범위와 한계를 보고한다. 단순 통과를 모델 전반의 안정성·품질·토큰 개선으로 확대하지 않는다.

평가를 설계하거나 판정할 때만 [평가 계약](references/evaluation-contract.md)을 읽는다. 특정 문장이나 agent에 맞추지 말고 반복되는 실패만 일반화한다.
