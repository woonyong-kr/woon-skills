# Quality

## 적용 우선순위

1. 보안·안전 정책과 도구가 강제하는 제약을 지킨다.
2. 저장소의 `AGENTS.md`, 아키텍처 결정, 공개 API와 빌드 계약처럼 반드시 지켜야 하는 제약을 확인한다.
3. 강제 제약과 충돌하지 않는 범위에서 사용자가 명시한 구조와 이번 작업에서 합의한 결정을 요구사항으로 적용한다.
4. 언어·프레임워크 스킬의 상세 규칙을 적용한다.
5. 위 기준에 없는 배치·책임·부수 효과는 [상세 코딩 기준](references/coding-standards.md)으로 결정하고, 이름은 `$naming`에 맡긴다.
6. 같은 역할의 기존 코드에서 확인한 일관된 관례를 마지막 보조 근거로 사용한다.

상위 기준과 하위 기준이 충돌하면 사용자의 지시를 조용히 무시하지 않는다. 충돌 지점과 가능한 대안을 설명한다.

## 필수 판단

1. 변경할 동작의 책임, 상태 소유자, 부수 효과와 성공 조건을 정한다.
2. 폴더·파일·클래스·함수 위치를 책임과 의존성 방향으로 결정한다.
3. 실제 경계가 없으면 새 계층, 인터페이스와 래퍼를 만들지 않는다.
4. 사용자가 요청한 정리 범위 안에서 일관성을 복구하고 관련 없는 변경은 보존한다.
5. 저장소가 제공하는 포맷→린트→타입 검사→테스트 순으로 좁은 검증부터 실행한다.

배치를 바꾸기 전에 강제 제약, `기존 → 변경` 매핑, 목표 트리, 호환성 유지 항목과 검증 방법을 확정한다. 한두 파일만 담는 대칭형 계층 폴더를 기본안으로 제안하지 않는다.

배치·파일 분리·부수 효과를 판단할 때만 상세 코딩 기준을 읽고, 이름을 만들거나 고칠 때는 `$naming`을 함께 사용한다. `.woon/repository.yaml`이 있거나 Woon 저장소 간 소유권을 판단할 때만 [Woon 저장소 규칙](references/woon-repository.md)을 읽는다. 실행하지 않은 검증은 통과로 표현하지 않는다.
