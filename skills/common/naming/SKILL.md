# Naming

강제된 공개 계약과 사용자가 지정한 이름을 먼저 지킨다. [사용자 어휘](references/vocabulary.md)에서 대상 표현을 검색하고, 새 이름·동사·접미사·Boolean·개수·단위·호환성을 결정할 때 [의미 기준](references/semantics.md)의 해당 절만 읽는다. 대소문자, 파일명과 package/module 규칙은 `$python`, `$java`, `$ts` 같은 해당 언어 스킬이 소유한다.

1. 이름을 붙일 대상의 소유 도메인, 역할, 행동과 단위를 정한다.
2. 공개 API, import, 직렬화, reflection, 이름 기반 주입과 저장 형식 사용처를 검색한다.
3. `기존 이름 → 새 이름 → 선택 근거`를 작성한다.
4. 기본형은 함수 `행동 + 도메인 대상`, 타입 `도메인 대상 + 역할`로 제한한다.
5. 매개변수가 설명하는 조건과 구현 단계를 이름에 반복하지 않는다.
6. 사용자 어휘의 선호·금지·대체 규칙을 적용한다.
7. 언어 스킬의 표기법을 적용하고 저장소 전체에서 충돌을 다시 검색한다.
8. 실제 외부 소비자가 확인될 때만 호환 alias나 adapter를 둔다.

완료 전에 포괄 이름을 다른 포괄 이름으로 바꾸지 않았는지, 이름이 부수 효과와 존재 여부 계약을 숨기지 않는지, 사용자의 어휘 변경이 단일 정본에 반영됐는지 확인한다.
