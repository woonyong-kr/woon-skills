# Humanize

독자에게 필요한 말이 자연스럽게 이어지도록 고친다. 문장을 멋있게 만들려고 사실, 의미, 감정이나 근거의 강도를 바꾸지 않는다. 단어를 AI 작성의 증거나 금지어로 취급하지 않는다.

1. 대상 독자와 글의 용도, 편집 가능한 본문을 확인한다. 사용자가 준 말투와 현재 형식을 우선한다. Wiki 설명은 보통 `-다`, 안내는 `-합니다` 또는 `-해요`로 맞추되 이미 자연스러운 문체를 일괄 변환하지 않는다.
2. 원문에서 누가 무엇을 왜 하는지, 조건·예외·추정·날짜·수치·출처가 무엇인지 읽는다. 의미를 확정할 근거가 없으면 구체적인 사실을 보태지 않는다. 부족한 정보가 있어도 확인 가능한 문장의 교정은 계속한다.
3. [문장 교정 기준](references/korean-prose.md)의 다섯 관점으로 문맥을 검토한다. 결함이 있는 부분만 고치고, 목록·키워드 트리·제목이 탐색에 쓰이면 그 구조를 보존한다.
4. 수정 전후를 읽고 같은 정보와 논리 순서가 남는지 대조한다. 문장 길이와 끝맺음이 기계적으로 반복되거나, 매끈하지만 뜻이 흐려졌다면 한 번 더 고친다. 좋은 문장은 그대로 둔다.

## 보존 경계

- 기술 용어·고유명사·API·identifier는 원문 표기를 유지한다. 익숙한 기술 영어를 억지로 순화하지 않는다.
- 인용, 법적 문구, 원자료, 코드·출력·수식·그림 원본을 문장 교정 대상으로 바꾸지 않는다. 개인 메모와 발화는 작성자의 말투와 뜻을 보존한다.
- `(추정)`, `(임시)`, 실패·미확인·미완료 표시와 개인·팀 기여를 지우지 않는다. 불확실한 내용을 단정으로 바꾸지 않는다.
- 숫자·날짜·단위·원인과 결과·조건·부정의 범위를 그대로 둔다. 필요 없는 표현을 줄인다는 이유로 설명, 반례나 주의를 요약 삭제하지 않는다.
- 링크의 표시 문구만 고칠 때도 목적지·anchor·참조 ID를 유지한다. 페이지·제목·파일명·목차 구조 변경은 별도 승인 범위와 `$knowledge-navigation` 계약을 따른다.

## Woon 저장과 전수 검토

기술 사실과 학습 전개는 `$tech`, 정본 저장은 `$archive`·`$compile-knowledge`가 소유한다. compiler가 만든 Markdown을 직접 고쳐 다음 생성에서 사라지는 수정을 만들지 않는다. source 원본은 보존하고 편집 가능한 claim·page 입력이나 승인된 책 reader를 고친다.

책의 제공 판본 언어 판정과 교정 허용 범위는 [책의 공통 목차·원문 보존 계약](repo://skills/skills/knowledge/knowledge-navigation/SKILL.md#단일-트리-계약)를 먼저 따른다. 원문·번역·학습자 보강을 구분하고 허용된 문장 교정에서도 source element와 exact-once coverage를 보존한다. delivery span이 달라지면 해당 manifest와 receipt를 소유 경로에서 함께 갱신한다. 문장 교정 요청만으로 멈춘 번역·원자료 복구·책 전권 재작성을 재개하지 않는다.

전수 요청은 현재 편집 대상의 경로·revision 목록을 고정한 뒤 각 문서를 읽고 `수정`·`유지`·`제외 사유`를 구분한다. 검사기의 일치 수나 표본 몇 개로 전체 문장을 검토했다고 보고하지 않는다. 목록은 최신 진행 상태 하나로 유지하고 원고 옆에 중복 보고서를 쌓지 않는다. 미완료 범위와 실제 반영·재생성 검증을 구분한다.

긴 파일에서 검토할 위치를 찾을 때만 다음 읽기 전용 검사를 사용할 수 있다.

```bash
python "$(woon resolve repo://skills/skills/writing/humanize/scripts/audit_korean_text.py)" --json path/to/document.md
```

검사기는 frontmatter·코드·수식·인용·링크 목적지를 제외한 표현 후보를 출력한다. 자동 치환이나 통과 gate가 아니며 결과가 없어도 의미·말투 검토는 필요하다. 맞춤법·단어 뜻의 판단 근거가 필요할 때만 [국어 자료](references/korean-prose.md#국어-자료)를 조회한다.

요청이 교정이면 수정본을 먼저, 검토이면 실제 문장과 수정안을 먼저 보여 준다. 말투 변경이나 보존한 표현 등 결과 판단에 필요한 차이만 짧게 설명한다.
