# tech-blog-writing

## 이 스킬이 하는 일

- `docs/` 레포로 유입되는 모든 마크다운 포스트에 일관된 톤과 구조를 적용한다.
- 적용 범위는 분류(KEEP/EDIT/REWRITE/SPLIT) 와 무관하게 "복사·이관·편집되는 모든 문서" 다. KEEP 라 해도 최소한 본 문서의 **금지 패턴 체크리스트** 는 반드시 통과해야 한다.
- 입력은 키워드·원본 초고·사용자의 짧은 지시이며, 출력은 프런트매터를 포함한 완성 포스트 `.md` 본문이다.

## 기본 원칙

1. **사실 > 수사.** 팩트·수치·근거가 먼저. 인상평·자기계발 어휘는 제거한다.
2. **합쇼체 고정.** "~합니다/~합니다만/~합니다. 다만" 류를 기본으로 둔다. 반말·해요체 금지.
3. **담백한 구어체.** 설명이 길어져도 말투를 꾸미지 않는다. 수식어·감탄·의성어를 쓰지 않는다.
4. **한 줄 한 주장.** 한 단락은 한 논점으로 모은다. 병렬 나열은 목록으로 분리한다.
5. **원본 보존.** 원본의 기술적 사실은 바꾸지 않는다. 불확실하면 "원본 확인 필요" 로 남긴다.
6. **이모지·AI 흔적 제거.** 이모지, "생성된", Claude/AI 공동 저자 표시, 로봇·스파클 기호 사용 금지.

## 톤 규약

- 종결어미: `~합니다`, `~합니다만`, `~합니다. 다만 …`, `~합시다`, `~합니까?`.
- 설명 접속: `그리고`, `다만`, `한편`, `즉`, `예를 들어`, `정리하면`.
- 금지 어휘 예: "놀랍게도", "간단히 말해", "결국에는", "반드시 기억해야 하는", "무조건", "필수적으로".
- 1 인칭 "저" 는 허용. 과도한 자기 서사(회고·감상) 는 한 단락 이내로 제한한다.

## 10 단계 구조

1. **제목 (H1)** — 포스트 주제를 15 자 이내로 압축. 키워드 앞에 형용 수식 금지.
2. **부제/요약 1~2 문장** — 이 글이 다루는 범위를 선언.
3. **문제 설정** — 어떤 상황에서 이 개념이 필요해지는지 한 문단.
4. **정의** — 키워드의 공식 정의. 가능하면 출처 인용.
5. **구성 요소** — 개념을 이루는 부분·단계·유형을 나열.
6. **동작 원리 / 절차** — 실제로 어떻게 흘러가는지. 필요하면 의사코드·도식.
7. **예시** — 구체적 수치·사례 1~2 개. 억지 비유 금지.
8. **자주 묻는 오해** — 혼동 포인트 혹은 흔한 오답.
9. **경계·한계** — 적용되지 않는 경우·전제 조건.
10. **정리와 다음 학습 키워드** — 한 문단 요약 + 이어질 키워드 2~3 개 링크.

- 모든 포스트가 10 단계를 꽉 채울 필요는 없다. 짧은 글이면 3·4·6·10 만 있어도 충분하다. 다만 순서는 지킨다.

## 제목·부제 규칙

- 제목은 "키워드 — 핵심 질문" 또는 "키워드 개요" 류. 과장·수사 금지.
- 부제는 포스트 첫 문단 또는 H2 로 배치. 따옴표·대괄호로 꾸미지 않는다.
- 한 포스트에서 H1 은 1 회만. 이후는 H2·H3 를 사용한다.

## 프런트매터 스펙

모든 포스트는 다음 블록을 최상단에 둔다.

```yaml
---
title: 포스트 제목
category: CS 기초               # L0 폴더명과 일치
keyword: 실수 표현법            # L1 폴더명과 일치
subkeyword: 부동 소수점          # L2 이하 폴더로 승격된 경우의 가장 구체적인 폴더명
created: 2026-04-20             # 필수, YYYY-MM-DD, 수기 입력
updated: 2026-04-20             # 필수, YYYY-MM-DD, 수기 입력
tags: [IEEE-754, precision]     # 선택
summary: 1~2 문장 요약          # 선택
source: _krafton/.../원본.md    # 원본이 있으면 명시 (선택)
---
```

- `created`/`updated` 는 자동 주입되지 않는다. 반드시 사람이 넣는다.
- `category`/`keyword`/`subkeyword` 는 실제 폴더 위치와 일치해야 한다. CONTRIBUTING.md 4.3 절 우선.
- `subkeyword` 는 L2 이상 깊이의 폴더일 때만 채운다. 중간 계층이 아니라 "가장 구체적인 폴더" 를 쓴다.

## 입력 처리

- 호출자는 원본 텍스트와 목표 키워드(category/keyword/subkeyword?) 를 함께 전달한다.
- 원본이 없으면 키워드만으로 빈 틀을 만들고, 본문 자리에는 `(미작성)` 플레이스홀더를 둔다.
- 다중 주제가 섞인 원본은 분할한다. 분할 결과는 각각 독립 포스트로 반환한다.

## 출력 포맷

- 반환은 "프런트매터 + 마크다운 본문" 한 덩어리.
- 본문 최상단 헤딩은 H1, 이후는 H2/H3.
- 코드 블록은 언어 힌트를 반드시 붙인다 (````python`, ````c`, ````text`).
- 각주·인용은 Markdown 표준 문법만 사용한다. Hugo·MDX 확장 금지.

## 금지 패턴 체크리스트

모든 출력(복사만 하는 KEEP 포함) 은 아래를 통과해야 한다. 하나라도 걸리면 수정 후 반환한다.

- 이모지·유니코드 심볼(`🎯`, `✨`, `⭐` 등) 포함
- "Co-Authored-By: Claude", "Generated with Claude" 류 AI 흔적
- 반말·해요체 혼용
- "반드시", "무조건", "완벽한", "최고의" 같은 단정·과장 어휘
- 자기계발·동기부여 어휘 ("성장", "도전", "파이팅")
- 의미 없는 접속사 남발 ("그래서", "그러니까", "일단")
- 근거 없는 수치 ("대부분", "거의 모든") 를 데이터 없이 사용
- 원본에 없는 사실을 창작해 삽입
- 알고리즘 문제 풀이 원본을 그대로 이식 (개념 문서가 아니라면 이관 대상 아님)

## 품질 기준

- 한 포스트 길이: 400 ~ 1500 자 기본. 1500 자를 넘기면 분할 여부를 먼저 판단한다.
- 목록 vs 단락: 병렬·나열은 목록, 추론·흐름은 단락.
- 표: 3 열 이상의 비교에서만 사용. 2 열 비교는 문장으로 처리.
- 외부 링크: 공식 문서 우선 (MDN, RFC, 각 언어 공식 docs). 블로그 링크는 신뢰 가능한 경우에만.

## 호출 예시

```
입력:
  category: CS 기초
  keyword: 실수 표현법
  subkeyword: 부동 소수점
  원본: (Krafton 강의 발췌 텍스트)
출력:
  ---
  title: 부동 소수점 - IEEE 754 의 구조
  category: CS 기초
  keyword: 실수 표현법
  subkeyword: 부동 소수점
  created: 2026-04-20
  updated: 2026-04-20
  ---

  # 부동 소수점 - IEEE 754 의 구조
  ...
```

## 분할 절차

1. 원본을 읽고 포함된 "독립 주제" 를 나열한다.
2. 각 주제가 별도 포스트로 성립할 분량(최소 400 자) 인지 판정한다.
3. 성립하면 각각 별도 호출로 재진입하고, 못 되면 하나로 합치거나 드롭한다.
4. 분할한 포스트들은 같은 폴더(또는 필요 시 새로 승격한 L2 폴더) 에 둔다 (CONTRIBUTING.md 1.2 절).

## EDIT vs REWRITE 차이

- **EDIT**: 원본 골격을 유지한 채 톤·용어·금지 패턴만 수정한다. 본문 순서·예시는 원본을 따른다.
- **REWRITE**: 골격부터 10 단계 구조로 재조립한다. 원본 문장은 참고용일 뿐이며, 같은 사실을 새 문장으로 다시 쓴다.
- **KEEP**: 본문은 원본 유지. 다만 프런트매터 보강과 금지 패턴 제거는 필수다.
- **SPLIT**: 분할 절차 적용.
- **MERGE**: 여러 원본을 주제 하나로 통합. REWRITE 에 준한다.
